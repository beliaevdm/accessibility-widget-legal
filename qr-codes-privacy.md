## 3. Information the app processes

**Codes created by the site owner:** the content of each code (a link, a Wi-Fi network name and password, contact
card details, an email address, a phone number, a message or text), its name and design. The name is visible only
to the site owner.

**Editable codes:** for each editable code the app creates a redirect in the site's own SEO settings, from the site's
address `/qr/<short name>` to the link the site owner chose. The app reads the site's published address and plan from
Wix to do this.

**Visitors:** the app collects **no personal data from visitors**. Scanning happens on the visitor's own phone, and
editable codes are answered by the site itself; the app does not count or record scans. When the widget shows a code of
the current page, that address is turned into a code in the visitor's browser.

## 4. Cookies and browser storage

The app **does not set any cookies**. In the visitor's browser the widget uses `sessionStorage` to keep a copy of the code for faster loading;
it is cleared when the tab is closed. In the site owner's dashboard, `localStorage` remembers whether a short review request was already shown.

## 5. Third-party services

The app uses **no analytics, tracking, advertising or short-link services**. A logo in a code loads from the site's
own Wix media. Links inside codes open only when someone scans or taps them.

## 6. How long data is kept, and how to delete it

Codes stay in the site's Wix collections until the site owner deletes them in the app dashboard or in the site's CMS. When
deleting an editable code the site owner chooses whether its redirect stays (so printed copies keep working) or is
removed; redirects can also be removed in the site's SEO settings.
